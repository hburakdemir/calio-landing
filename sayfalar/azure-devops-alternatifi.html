Azure DevOps ve TFS Alternatifi: Basit, Türkçe, Kendi Sunucunuzda

Yayın tarihi: 7 Ağustos 2026

Azure DevOps (Boards, Repos, Pipelines, Test Plans, Artifacts), Microsoft ekosistemi etrafında geliştirme yapan büyük ekipler için tasarlanmış kapsamlı bir DevOps paketi. Kanban/görev takibi bu paketin yalnızca bir parçası — geri kalanı sürüm kontrolü, CI/CD ve test yönetimi. Sadece ekip görev takibi ve iletişimi arayan bir KOBİ için bu kapsam çoğu zaman gereğinden fazla.

TFS kullanıyorsanız

Team Foundation Server (TFS), Microsoft tarafından 2019'da Azure DevOps Server olarak yeniden markalandı — aynı ürün ailesinin kendi sunucunuza kurulan sürümü. Kaynak: Microsoft Learn — "TFS rebrand to Azure DevOps Server". Şirketinizde hâlâ "TFS" adıyla anılan bir kurulum çalışıyorsa, muhtemelen bu ürün ailesinin daha eski bir sürümüdür. Bu sayfadaki karşılaştırma ve taşıma bilgileri hem Azure DevOps (bulut) hem Azure DevOps Server / TFS (kendi sunucunuz) için geçerlidir.

Neden Azure DevOps / TFS'ten çıkılıyor?

1. Kurumsal karmaşıklık. İş öğesi tipleri, süreç şablonları (Agile/Scrum/CMMI), sprint/backlog/board hiyerarşisi ve alan (area) / iterasyon yapılandırması — büyük yazılım organizasyonlarının ihtiyacı için tasarlanmış. 10-30 kişilik bir ekip için bu yapılandırma yükü, panoyu kurup çalışmaya başlamaktan daha uzun sürebilir.

2. Microsoft ekosistemine kilitlenme. Kimlik doğrulama tipik olarak Microsoft Entra ID (eski adıyla Azure AD) üzerinden yürür, lisanslama Visual Studio abonelikleriyle iç içe geçmiştir ve derin entegrasyonların çoğu .NET/Azure merkezlidir. Farklı bir yığın kullanan ya da yalnızca görev takibi arayan bir ekip için bu, gerekmeyen bir bağımlılık katmanı.

3. Lisans modeli tek başına karmaşık. Bulut tarafında (Azure DevOps Services) Basic plan ilk 5 kullanıcı ücretsiz, sonrası kullanıcı başına 6 USD/ay; test yönetimi eklendiğinde kullanıcı başına 52 USD/ay'a çıkıyor. Kaynak: azure.microsoft.com — Azure DevOps Services Pricing, 7 Ağustos 2026. Kendi sunucunuza kurduğunuz sürümde (Azure DevOps Server) ise ayrıca bir sunucu lisansı + kullanıcı başına CAL (client access license) gerekiyor; Visual Studio abonelik yoluyla alınırsa Professional için kullanıcı başına 45 USD/ay, Enterprise için 250 USD/ay'a kadar çıkabiliyor — üstüne Windows/Windows Server lisansı ayrıca gerekiyor. Kaynak: azure.microsoft.com — Azure DevOps Server Pricing, 7 Ağustos 2026.

Azure DevOps / TFS'ten Calio'ya taşıma

Azure DevOps API anahtarınızı girip projenizi seçiyorsunuz. Aktarılanlar:

  • Board'lar ve kolon düzeni
  • İş öğeleri (work item) — başlık ve açıklamalarıyla, kart olarak
  • Son tarihler
  • Öncelikler
  • Durumlar (Yapılacak · Devam Ediyor · Tamamlandı eşlemesiyle)
  • Etiketler, renkleriyle birlikte

Aktarılmayanlar — bunu baştan söylüyoruz: yorumlar, ek dosyalar ve kişi atamaları bu sürümde taşınmıyor; iş öğesi tipleri ve süreç şablonu özel alanları (custom field) aktarılmıyor. Atamaları içe aktarımdan sonra ekibinizle dakikalar içinde yapıyorsunuz. Tek içe aktarımda 500 kayda kadar taşınır.

Sık gelen üç itiraz

"Pipeline'larımız (CI/CD) Azure DevOps'a bağlı."

Doğru olabilir — Calio bir CI/CD aracı değil, kanban ve ekip iletişimi aracı. Pipeline/Repos/Artifacts kullanmaya devam edip yalnızca görev takibi ve iletişimi Calio'ya taşıyan ekipler var; bunu demo görüşmesinde konuşalım.

"Zaten Visual Studio/Microsoft 365 lisansımız var."

Anlaşılır — mevcut lisans zaten ödendiyse geçişin maliyet gerekçesi zayıflar. Ama ekibinizin bir kısmı yalnızca görev takibi için Azure DevOps'un iş öğesi karmaşıklığıyla uğraşıyorsa, daha sade bir kanban katmanı yine de zaman kazandırabilir.

"Ekibim yeni araca alışamaz."

Calio bilinen kanban düzenini kullanıyor: liste, kart, sürükle-bırak — Azure DevOps'un Boards görünümünden çok daha az yapılandırma gerektirir. Arayüz Türkçe ve İngilizce. Deneyin: demo.calio.space

Calio kimin için doğru değil?

Dürüst olalım:

  • Büyük, Microsoft-stack kurumsal ekiplersiniz — Visual Studio Enterprise lisanslarınız zaten var, .NET pipeline'larınız Azure'a bağlı, gelişmiş test yönetimi (Test Plans) veya derin CI/CD entegrasyonu gerekiyorsa Azure DevOps bugün hâlâ mantıklı bir seçim olabilir.
  • Sürüm kontrolü ve build/release otomasyonunu da tek üründe istiyorsanız, Calio bunları sunmuyor — yalnızca kanban ve ekip iletişimi kapsıyor.
  • 200 kişilik bir organizasyonsanız ya da karmaşık iş öğesi hiyerarşisine (epic → feature → story → task) bağımlıysanız, Calio bugün için doğru seçim olmayabilir.

Bunları demo görüşmesinde konuşuyoruz. Size uymuyorsa bunu söylemek, satmaya çalışmaktan daha iyi.

Sıradaki adım

Azure DevOps ya da TFS panonuzu 30 dakikalık bir demoda canlı aktaralım. Satış baskısı yok; kendi kullanım senaryonuz üzerinden ilerliyoruz.
